# 分段：一集剧本 → shots/E01.md

讲怎么把 story/E01.md 拆成一段段视频生成、每段多长、装多少内容，以及用户贴分镜时怎么转写。用户给了镜头、分段或要求照原稿拍时，末节「导入已有分镜」优先于本组文件的调度建议。正文写法见 video-prompt.md，拼装见 prompt-anatomy.md。

## 落地形态

`shots/E01.md` 顶部按 `templates/shots.md` 写分段表。用剧中的角色名和造型、场景名和版本给用户看，多人同框按人列出，空镜写「无人」。交付已有分镜时也用这套表头呈现。

交付时在人物和场景旁标明各自的参考图状态。有图但尚未挂到本段视频节点的写「拟用参考图」，按文字描述的写「文字描述」。节点已建，用 `node get --key E01/S01 -j` 核对 `data.config.generation.references` 的别名和来源，与选定的图相符写「已绑定参考图」，来源不符标出哪张待更换，读不到写「待核对」。绑定指当前节点使用这张图，成片里的人物和场景一致性留到审片时看。

分段表下放逐镜预览，每个实际镜头一行，用剧中称呼简写景别、运镜和可见动作。交付时默认展示预览或给出文件顶部这两张表的入口。修改稿按最终正文更新预览，旧分镜的预览补在首个分镜小节之前。

每段选定的素材按段号记入表下「生成参考」注释，保留每个参考的别名和完整来源（含道具等参考）。提交时沿用这份映射，`--ref` 的别名与正文的 `{{别名}}` 逐字一致。旧分镜沿用原参考列中的绑定。

表和注释都放在第一个分镜小节之前。下面每段一个小节，正文原样提交给视频模型。新写的小节以段号开头（如 `## S01`），有标题就在段号后加空格（如 `## S01 雨夜·重逢`），两种都用 `--prompt-file 'shots/E01.md#S01'`。

引用已有小节时，若段号和标题用 `·` 连写，就把 `#` 后的小节名按原文完整传入（如 `--prompt-file 'shots/E01.md#S01·雨夜'`）。

## 两层粒度

| 层 | 是什么 | 约束 |
|---|---|---|
| 段 | 一次视频生成，产出 out/E01/S01.mp4 | 整数秒，在 `model describe` 给的时长范围内；参考数在它给的上限内 |
| 镜头 | 段内的一个时间区间，对应正文里的一个画面阶段 | 从 0 连续铺到段时长，不留空洞；一个镜头一个画面重心 |

模型一次生成里就能切镜、换景别、运镜、出台词和音效，段内的运镜和镜头跳变由模型连着拍，比跨段拼接自然，所以一次反打、一句台词结束只是新镜头，不是新段，段要装满到接近模型的时长上限（见「装箱」）。每段都要能单独重生成，正文自包含（见 video-prompt.md「只写摄像机拍得到的」）。

## 先查模型上限

时长范围、参考图/视频/音频数量上限、是否支持首尾帧，以 `jimeng-novel model describe --model-id <id>` 为准，不凭记忆，查不到就告诉用户。超出范围的段可能被拒，也可能和预期不同（如时长变短），费用按实扣。换模型后上限变小，超长的段按叙事事件拆开，台词和镜头顺序不变；上限变大，还没生成的段按新上限重新装箱，已经生成、用户满意的段不动。

常用视频模型（数值会变，以 `model describe` 的实时结果为准）：

| 模型 | 时长 | 参考上限 | 分辨率 | 首尾帧 |
|---|---|---|---|---|
| Seedance 2.5（`Seedance_2.5`） | 4–30 秒 | 图 30、视频 10、音频 10，合计 50 | 480p–4k | 支持 |
| Seedance 2.5 Flash（`Seedance_2.5_flash`） | 4–30 秒 | 图 10、视频 5、音频 5 | 480p、720p | 支持 |
| Seedance 2.0 VIP / 2.0 Fast VIP（`seedance2.0_vision` / `seedance2.0_fast_vision`） | 4–15 秒 | 图 9、视频 3、音频 3 | VIP 480p–4k；Fast 480p、720p | 支持 |
| Seedance 2.0 mini（`Seedance_2.0_mini`） | 4–15 秒 | 图 9、视频 3、音频 3 | 480p、720p | 不支持 |

首尾帧模式不能和普通参考混用。

## 台词计时

所有能听见的文字都要计时：台词、路人喊声、电话广播、内心独白（os）、画外音和旁白（vo），漏算会被模型压成快嘴。

```
python3 <skill>/scripts/count_chars.py shots/E01.md --max-duration <模型上限>          # 写好分镜后逐段核算
python3 <skill>/scripts/count_chars.py --duration 10 "女主：……" "男主：……"             # 还没写进分镜时单段试算
python3 <skill>/scripts/count_chars.py --retime shots/E01.md#S02 --duration 12      # 改了某段时长后按原比例重排时码，看过 diff 再加 --write
```

分镜模式按分段表时长和引号里的台词逐段判超载，并逐个分镜核对（各分镜秒数之和等于段时长、「由以下N个分镜」对得上、每个分镜装得下自己的台词且最多 2 句），说话人取引号前最近的 `{{别名}}`；单段试算写成「角色：台词」才计换人停顿。字数秒数用脚本算，不手算。语速常量是经验值，用户反馈太快太拖就记进 README.md 的假设，后面照此调。

## 装箱

按剧本顺序把内容装进段，每段尽量装满：同一地点（同一场景版本）、时间连续的内容一直往里装，剧本里场号不同也算同场；再装就超时长、超参考数上限或对白超载（`count_chars.py` 报超载）时才切。装满说的是内容，时长仍按「定时长」的公式算，所以多数段接近上限、不一定正好等于上限。跨段拼接只能靠文字和尾帧去接，每多一个切点，人物位置、光线、景别就多一处可能跳的地方。

只有这几处切新段：换地点或换场景版本（一段挂一个版本，混挂会被当成换了地方）；时间跳跃、闪回进出；再装就超时长、参考数上限或超载；同一角色换造型（剧本要求当场换装时例外，挂两张造型图）。

- 开场钩子、集尾钩子、爆点反转不为它单独切段：开场钩子放在第一段的前 3 秒，集尾钩子放在最后一段的结尾，爆点和它的前因、第一反应装在同一段。一段里只有一部分不满意时，按 continuity.md「只重拍一段的后半」截掉重拍，不靠预先切碎来省重抽的钱。
- 一场戏超过上限要拆时，先算至少要几段（这场的总时长 ÷ 上限，向上取整），再在节拍边界大致均分，避免前几段装满、最后剩一个几秒的尾巴。节拍边界落不进这个段数时多分一段；各段长短不用一样，别出现明显的短尾巴就行。
- 一场戏本身装不满一段就让这段短，不跨地点硬凑，也不往里填空时间（见「定时长」）。

切点落在叙事节拍边界、动作完成之后。一句台词、一个动作不劈两半；问与答、命令与执行、揭示与第一反应、出手与受击这类最小因果放在同一段，劈开后后一段不知道前因。装不下时把铺垫挪到上一段、删不推进的停顿、把切点前移到触发事件之前，不把回应推到下一段（有意留悬念除外）。用尾帧衔接的同场段可以在开门、转身这类自然掩护点切，见 continuity.md。

## 定时长

```
段时长 = 台词耗时下限（含换人停顿）+ 不与说话并行的独立动作 + 0.5s 收束，向上取整
```

- 装满靠多装内容，不靠拉长时长：先按装箱把同场内容装进来，再用上式算时长；内容不够上限就取算出来的值，不先定成上限再往里填，空出的时间模型会用呆站、重复台词或胡言乱语填满。
- 独立动作逐项列（「推文件 1s、桌面特写 1s、男主反应 1s」），列不出来这段时间就不存在。纯画面段按视觉事件计，每个约 2-4 秒，全集合计不超过 1/3。
- 计算值不在可选取值里时取不小于它的最近合法值，多出的时间补真实动作（反应、走位、道具），不补静止画面。
- 分段表写好后，加总各段秒数。有剧本估时区间时和它比，超出区间就逐场对照独立动作、段尾收束和模型取整，说明哪场差了几秒。用户定了目标时长的，另和目标核对，超出时按铁律 2 处理。
- 分镜一级同样算：一个分镜的秒数不超过它的台词耗时加写明的动作再加约 1 秒，多出的时间写成开口前的具体动作；台词写在一段长推镜后面，人会先空站几秒。

## 单段内容量

| 段时长 | 对白上限 |
|---|---|
| ≤ 8s | 1-2 句，每句宜 ≤ 10 字 |
| ≤ 15s | 3-4 句 |
| > 15s | 按镜头分，每镜头 ≤ 2 句 |

- 每段至少 1 个叙事事件（改变局势的动作、推进剧情的台词、新信息），大约每 5 秒 1 个：10 秒至少 2 个，15 秒至少 3 个，30 秒至少 6 个。走路、站着、看风景不算。
- 硬切大约每 5 秒最多 1 个：8 秒以内最多 1 个，15 秒最多 3 个，30 秒最多 6 个。切得越碎，每个镜头越短，越容易被整镜跳过。长段里几个画面阶段之间优先用镜内调度串起来（跟拍、摇、焦点转移、人物走近或走出近景，见 dialogue-and-sound.md「对白调度」），比连着硬切顺。
- 动作的起手（拔刀）和结果（对方倒地）各占一个阶段、各有时长，只写结果起因会丢。剧情靠它成立的道具、动作和情绪节拍单独占一拍，给近景或特写停留 2–3 秒，放在全景背景里观众看不见。
- 每场先定除了出场角色还有谁在。剧本的「出场」只列说话或被拍到的角色，法庭的法官和旁听者、婚礼的宾客、街上的行人、办公大厅里的其他职员和排队的人都不会列，画面里却该有。按地点、时段和剧情定人数和他们在做什么：深夜后巷可以没人，白天开庭的法庭、办婚礼的礼堂不能是空的。定好写进导演方案，同场每一段照抄同一句，不能这段有人、下段没人。不写「空着」「空旷」「空无一人」，除非剧本写明那里没人。
- 群演不关键就放进背景，写人数和在做什么。出现在剧情关键镜头（爽点、围攻、众人反应）或人数本身是剧情时，先出群像参考（`assets/character-sheet.md`「群像图」），正文写清人数和各自站位；没有参考常出同脸、镜像、人数不对，这类镜头重做最贵。
- 超载时按铁律 2 腾地方：用户没定分段就拆段、在相邻段之间挪完整的句子，加时长是请用户选的选项。台词逐字保真，省略号破折号都保留；剧本台词本身有问题就回剧本改。

## 切镜头

镜头和正文的画面阶段一一对应，每个镜头想清楚这几项：

| 项 | 写法 |
|---|---|
| 时间 | 段内秒数，镜头通常 2-5 秒；对白按事件调度（见 dialogue-and-sound.md） |
| 景别 | 大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写，连续变化写「中景→近景」 |
| 角度 | 平视 / 仰拍 / 俯拍 / 过肩（从谁肩后拍向谁）/ 主观 / 侧拍 / 背拍 |
| 运镜 | 取自 video-prompt.md 的运镜表，带速度 |
| 动作 | 位置、绝对朝向、动作过程、结果 |
| 台词 | 说话人、逐字台词、声音质感和身体表现；os、vo 标明 |
| 声音 | 环境床 + 事件音；能听懂的人声算台词 |

## 节拍与情绪档位

给每段定一个叙事功能（开场钩子 / 建置 / 对峙升级 / 反击 / 反转 / 揭示 / 情绪落点 / 集尾钩子）和一个档位：

| 档位 | 含义 | 镜头倾向 |
|---|---|---|
| 蓄 | 压抑、铺垫、埋线 | 固定或缓推，中景多，光压暗 |
| 推 | 冲突加码、逼问、证据露角 | 正反打、过肩，节奏加快 |
| 爆 | 反击、打脸、真相、动作高潮 | 急推、手持冲击，硬光，环境音骤停后爆发 |
| 收 | 余波、决定、悬念定格 | 缓拉或固定，留一个可见的未完成问题 |

## 全集导演方案

写正文前在 shots/E01.md 顶部列持续状态清单（栏目见 `templates/shots.md`）：反复出现的道具各一个固定名称和一句外观；关键地标的位置、哪几段看得见，两侧都入镜的写两面；中途出现的状态变化首次出现时写死形态；关键陈设的数量位置；每段在场的人（离场要写出离场动作，否则会凭空消失或多出来）；站位锁和轴线锁（见 continuity.md）、关键动作用哪只手；每场的环境状态。各段正文从清单逐字取用（原因见 continuity.md「持续道具与环境」）；地标陈设照 `cast/<场景>.md` 当前版本，图重出改了描述就一起同步（见 workflow.md「改上游」）。

地标和站位先打开挂的场景图再写：门、窗、床头、大件陈设在哪面墙、朝哪边，主光从哪来，都从图里读，站位锁照 continuity.md 按人物和锚点写。剧情要的布局图里没有（多出一辆推车、要从另一头拍），先出新版本或反打的场景图，再写分镜。

然后在脑子里（或回复里）过一张「段｜时长｜功能·档位｜主运镜｜衔接」表，逐条判：

1. 开场 3 秒强信号：第一段 0-3 秒内出现可见冲突、异常或强关系句，没特征的中景人物开场观众会划走。起手可以是冲突直入、局部入场（鞋、手、背影）、建筑空镜、主观视角、承接上一集钩子。
2. 相邻段主运镜不同（主运镜是段内时长占比最大的运镜），否则成片看着像一个镜头在重复。
3. 情绪有起伏：不一路「推」到底；至少一个「爆」，之前有「蓄」或「推」；爽点阶梯升级，口头反击 → 证据 → 身份或资源 → 公开审判。
4. 集尾钩子落在画面上：最后 1-2 秒停在将揭未揭 / 将认未认 / 将赢未赢（悬念脸特写、证据露一角、门外脚步逼近、对峙定格）；只靠台词或问题不明的背影是弱钩子。
5. 呼应：至少一处镜头呼应，或一个道具的三态（出现 → 被使用 → 改变状态）。
6. 下一集起手：本集以悬念脸或对峙定格收，下一集用冲击台词开场；以危险逼近收，下一集用全景交代现场开场。

## 其余绑定

模型按字面读参考图，挂了什么就倾向画什么，所以只挂本段确实入画、且外观和图一致的东西。

本段要的样子和参考图不一样时，文字压不住图，场景、角色、道具都是这样：场景里多了或毁了大件东西，角色带着剧情要看清的伤和污渍跨几段，画面本身换了观感（见 video-prompt.md「屏幕里的画面、监控、回忆」）。剧情要观众看清的变化，以原图为参考派生一张该状态的图（母版句、换光句、变体前缀句见 prompt-anatomy.md），比白花一次视频钱便宜，从变化之后的段起挂它，露得再少也挂；一闪而过、不影响剧情的才只靠文字。同一样东西一段只挂一个状态的图，两张都挂会取错；状态切换放在段与段之间，或单独做一个特写段。

- 场景：同场连续的段用同一版本的同一张图，不因景别换图，换图会被当成换了地方。拍向图里看不到的方向（反打）或特殊视角（高处俯拍、窗外望进来）时模型会自编背景，这类机位要有自己的场景图（见 assets/scene-plate.md「反打与特殊视角」）。
- 角色：只挂本段完整入画（至少露脸或半身）的造型。多人段写明「画面中只有 N 人：…」，不入画的人不挂图、不写进站位，否则会多出一个人。不入画靠机位排除：这一拍的景别和朝向拍得到他所在的位置，就把他写进这一拍（位置、姿态、嘴唇紧闭）并挂图，不写他会凭空消失。画外发声的角色不挂图，写音色。背影、远景里的主角照样挂造型图（三视图有背面），不挂会被画成穿着相近的陌生人；只露手这类局部的不挂全身设定图，局部用 `## 设定` 里的原句写，需要一致时另出局部特写图。
- 道具：只挂本段出镜、且外观和参考图一致的道具；会变状态的随身物不画进角色图，或另出一个角色造型。有特写、或跨三段以上出现的道具出参考图。
- 写完按 shot-review.md 自检一轮。

## 导入已有分镜

用户贴镜头脚本（镜头1、镜头2……带台词）要直接出视频时：

- 原文存进 source/，只读，之后对照它核台词。
