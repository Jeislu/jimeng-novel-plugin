# 成片合成

一集的片段都在 `out/E01/` 下了，要拼成片、加字幕、BGM 或转场时看这份。合成不花积分，随时可以重来。

## 拼接和字幕：jimeng-novel compose

`jimeng-novel compose` 按顺序拼接片段、统一编码和尺寸、烧录 SRT（烧不了自动降级成软字幕，并说明原因），还能裁剪片段、输出接缝拼图。用法看 `compose --help`。片段顺序照 `shots/E01.md` 的分段表；只保留某段前半、或去掉模型在段末自己加的黑场时，用它的裁剪参数，不另外手写 ffmpeg，也不为黑场重生成。

## 字幕怎么写

有台词就默认做字幕，用户说不要才不做。台词和字卡分两份：台词时间轴交给识别，字卡自己写。参数以 `transcribe --help`、`compose --help` 为准。

按段做字幕，重做哪段就只重新识别那段：

1. 每段一份台词：`lines/E01/S01.txt`，把这段的台词照 `story/E01.md` 逐字、按顺序写进去，一行一条字幕。一条别太长：中文不超过约 12 字，英文不超过约 84 个字符（两行），长句在标点处拆成两条。屏幕上的换行交给 compose（英文只在词间断开），文件里不手动换行。没有台词的段不写文件。
2. `jimeng-novel transcribe out/E01/S02.mp4 out/E01/S03.mp4 … --text-file lines/E01/ --srt subs/E01/ --wait 180`（只传有台词的段）：逐段识别，文字用文件原文，时间轴取识别结果；数字的写法和念法（「K-205」和「K two oh five」）CLI 会当成同一句。看输出的两类问题：
   - `unmatched`：对不上的行。CLI 已经按前后句估了时间写进 SRT（`placement` 说明放在哪），先判断是漏说、说错还是拆行不合适；修了再跑。确认画面里说了、只是没对上的，核对估的时间，不准再手改那段 SRT。
   - `extra`：多出来的语音，多半是模型自己加的画外音或台词，按 `shots/shot-review.md` 决定重做还是接受。
   - `status` 是 `no_speech`：没认出人声，不算失败、不写 SRT。台词只有一两个词时 CLI 会按本地人声估时间写进 SRT（标 `lowConfidence`，要核对）；给了 `warning` 说明这段台词多半没生成出来，回去重做那段。服务端回「服务器繁忙」时 CLI 会自己分段重识别，不用写重试。

   识别可能扣积分但 `credit estimate` 报不出，报价时单列一行「字幕识别，计费见 `transcribe --help`」，和这一批视频一起确认，不为它单独请示；同一文件再跑同一条命令会复用结果。
3. 画外音、内心独白在 SRT 对应行加 `<i>…</i>` 斜体。
4. 字卡也按段写：`subs/E01/S02.cards.srt`，时间从这段 0 秒起，compose 按各段实际时长（含裁剪）自动排到整集，不用自己算起点。剧本里的【字幕：姓名·身份】从该角色的脸第一次清楚入画那一刻起（用 `frames` 找，段开头常是背影或局部）；剧情关键的文字和数字（时间、金额、编号）也在这里叠加，不交给视频模型画。只写内容本身（「23:47 末班车」），不加「车票：」「手机消息：」这类标签。每张至少停 2 秒；字卡在上部、台词在底部，可以同时出现，内容绑在画面物体上的（屏幕、票据）覆盖那个物体可见的全程，起点不早于画面里那件事发生的那一帧（屏幕变红、纸条递出）。字卡只能放在画面上部，贴不到物体上，分镜里别写「叠在某物上」，要对位就让那个镜头里的物体在上半部。长字卡 compose 会自动换行、缩小字号。
5. `jimeng-novel compose --clip out/E01/S01.mp4 … --clip-srt subs/E01/ --clip-cards subs/E01/ --even-volume --out out/E01.mp4`。台词在底部，字卡在上部、样式不同。`--even-volume` 按台词时间把各段人声拉齐：各段分开生成，段与段的人声响度可能差得很多，同场相邻两句会忽大忽小；输出的 `gainDb` 是每段调了多少，整段刻意压低或喊叫的段被调了就听一下。重做某段后，重新识别那一段，再合成一次。

用户要双语字幕时，先按原文语言做完上面几步，再给每条字幕和字卡加一行译文（加在 `subs/E01/` 的 SRT 里，重新识别过的段要重新加）。每条写两行：中文一行在上，另一种语言一行在下；compose 认出这种写法就按双语排，下面那行字号是上面的 0.8 倍（`--sub-second-scale` 调）。译文要口语、贴人物，原文一字不改。

合成后用 `jimeng-novel frames --at` 在每张字卡和每条挂了 4 秒以上的字幕的中点抽帧看：字幕不压人脸，字卡不挡主体，手机上看得清；在每条字幕的起点抽帧，确认张嘴的是说这句的人，起点比开口早一秒以上就改那段 SRT。字号偏大偏小用 `--sub-scale` 调，离底边的距离用 `--sub-margin`，花背景上看不清换 `--sub-style box`。不用 PIL 逐帧画字幕。平台会自动识别字幕时用软字幕或不加。

## BGM 与转场

片段生成时不要 BGM：每段独立生成，音乐在切点会断开跳变。BGM 在合成后统一混，只用用户提供或确认可用的音乐，音量压在台词下面：

```bash
ffmpeg -y -v error -i out/E01.mp4 -stream_loop -1 -i bgm.mp3 -filter_complex "[1:a]volume=0.15[b];[0:a][b]amix=inputs=2:duration=first:normalize=0[a]" -map 0:v -map "[a]" -c:v copy -c:a aac out/E01.bgm.mp4
```

段与段之间默认硬切。要黑场转场时在后期给相邻两段加淡出淡入，不要写进视频 prompt，模型会把黑场当成画面内容生成。

## 超分：要更高清的成片时

片段默认按 720p 生成。用户要 1080p 以上的成片时，先用 720p 片段合成并定稿，再对成片整体跑一次 `jimeng-novel upscale`，不必每段都用高分辨率重新生成：改片、重拍都在 720p 上做，定稿后只超分一次。版本有快速版、标准版、影院版，越往后细节越好、越贵，各分辨率可选的版本和参数看 `upscale --help`。

超分是服务端处理，要花积分，`credit estimate` 报不出价：报价时单列一行「超分（版本、目标分辨率），按实扣」，和用户确认后再跑，报花费用命令输出的实扣。字幕先烧进 720p 成片再超分，或在超分后的成片上重新合成字幕，两种都可以；超分后用 `frames` 抽几帧确认画面没有变形、字幕清楚。

## 交付

每合好一集或全剧，当轮就把最终 MP4 交给用户。按 `compose` 返回的 `path` 找到文件，做过混音或超分时用最后输出的版本。用宿主的视频附件或文件卡片发送，写明哪一集或全剧、实际总时长和字幕方式。附件发不了时，优先给宿主提供的可访问文件链接。只有文件路径时，给绝对路径并说明文件在哪台设备或哪个工作区。

同一份 MP4 也放上当前剧的画布。下面用第 1 集举例，上传时换成实际交付的文件。

```bash
jimeng-novel resource upload --file out/E01.mp4 --wait 600          # 返回 assetId
jimeng-novel node batch --input '{"nodes":[{"key":"E01/成片","type":"video","name":"第1集成片","assetId":"<assetId>"}]}'
```

多集都合完后再拼一条全剧（`compose --clip out/E01.mp4 --clip out/E02.mp4 … --out out/全剧.mp4`），同样交付，key 用 `全剧/成片`。重做后把新版上传，用原 key 在同一条 batch 记录中换成本次的 assetId 再提交。

建好节点后按「画布上放什么」跑 `project.py canvas push`。用 `jimeng-novel node get --key E01/成片 -j`（全剧换对应 key）核对 `data.state.selectedAssetId` 与本次上传的 assetId 一致。用 `jimeng-novel canvas get -j` 取实际分组和 `data.url`，在交付消息里给可点击的画布链接，并告诉用户在哪看，如「第1集分镜 → 第1集成片」（组内第一个）。全剧在「全剧成片」组。上传、同步或回读遇阻时照常交付已合好的文件，说明画布哪一步还没完成。

请用户重点看开场 3 秒、集尾钩子是否落在最后一个画面、段间有无跳变（compose 的接缝拼图可以先自己看一遍）。不满意的段只重做那一段再重新拼（根因判断见 `shots/shot-review.md`）。别断言「没有 BGM」：视频模型可能在音轨里自带氛围音乐，你听不到就没法确认。如实说「生成音轨里可能带氛围音乐」，用户在意时给办法：重生成该段，或合成时压低、替换原音轨。
